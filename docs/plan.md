# Rust学習プロジェクト最終確定版

## この計画の目的

この計画は、Rustを「最小の単位から」「前の理解なしでは次に進めない必然的な連鎖」の中で学ぶための、実行用ドキュメントである。

この文書は学習計画の正本であり、セッション運用ルールは `AGENTS.md`、現在地の管理は `PROGRESS.md` を参照する。

目標は次の2つである。

1. Rustの主要概念に違和感なく接続できる土台を作る
2. 最終的に、自分で設計して作り切った成果物を持つ

この計画は、Rustの全てを網羅するものではない。  
最初の本命プロジェクトとして、今後の自走に必要な土台を作ることを目的とする。

---

## 採用するプロジェクト

採用する題材は、**ミニ言語インタプリタを作り、その言語を使った実用CLIツールを作るプロジェクト**である。

一言で言うと、次の構成で進める。

1. フェーズ1: 言語のコアを作る
2. フェーズ2: その言語で現実の問題を解く

最終成果物は、**自作の小さなスクリプト言語で、成績計算や条件判定を処理できるCLIツール**である。

---

## なぜこの案なのか

この案を採用する理由は明確である。

1. 「文字列を読む -> 分解する -> 構文にする -> 評価する -> 動かす」という必然的な連鎖が強い
2. `String`、`Vec`、`HashMap`、`Result`、`trait` など、Rustの実務でよく出る概念が自然に登場する
3. 前半で理解を積み上げ、後半で実用性に接続できる
4. CHIP-8よりも、日常的なRustコードに近い
5. 個人開発や将来のアプリ開発に、より直線的につながる

---

## 学習哲学

この計画は、次の原則で進める。

1. 新しい概念は、必ず「今なぜ必要か」を先に確認する
2. 抽象概念は、先に具体例で理解してからRustコードに落とす
3. 一度に広げすぎず、1ステップ1責務で進める
4. 先に動く最小版を作り、その後で整理する
5. 便利そうでも、先の概念を先取りしない
6. テストは早い段階から小さく書き始める
7. エラー位置情報は後付けせず、最初に仕込む

---

## プロジェクト構成

### フェーズ1: ミニ言語のコアを作る

目的:

Rustの基本構文と設計の考え方を、必然的な依存関係の中で学ぶ。

到達点:

数値、変数、四則演算、比較、`if`、`while`、`print` が使え、REPLとファイル実行ができる小さな言語を作る。

### フェーズ2: その言語を使った実用CLIを作る

目的:

フェーズ1で作った言語を教材で終わらせず、現実の問題を解く道具にする。

到達点:

入力ファイルを読み、成績計算や条件判定ができるCLIを作る。

---

```text

```

## フェーズ1の実装ステップ

### Step 1. 基本型・変数・関数

扱う内容:

- `i64`
- `bool`
- `let`, `mut`
- 関数定義と戻り値

ここでの成果:

- 数値計算を関数として分けて書ける

補足:

- 最小構成を守るため、この段階では `f64` は入れない
- 小数が必要になった時点で、拡張として追加する

---

### Step 2. 文字列・スライス・位置追跡

扱う内容:

- `String`, `&str`
- 文字列の走査
- `Position { line, column }` の考え方

ここでの成果:

- 入力文字列を受け取り、「今どこを読んでいるか」を追跡しながら進められる

初期方針:

- 最初は**ASCII前提**で字句解析器を作る
- UTF-8の厳密な文字境界は、必要になった段階で別途学ぶ

補足:

- 位置情報は後付けすると設計変更が広がるため、この段階で仕込む

---

### Step 3. `TokenKind` と `Token` を定義する

扱う内容:

- `enum TokenKind`
- `struct Token`
- `match` による分岐
- `Position` をトークンに載せる

最小設計:

```rust
struct Position {
    line: usize,
    column: usize,
}

enum TokenKind {
    Number(i64),
    Plus,
    Minus,
    Identifier(String),
}

struct Token {
    kind: TokenKind,
    position: Position,
}
```

ここでの成果:

- `1 + 2` のような入力を、位置情報付きのトークン列に分解できる

テスト運用開始:

- この段階から `#[test]` と `assert_eq!` を道具として使い始める
- テストの体系的な整理は後のStep 14で行う

例:

```rust
#[test]
fn test_tokenize_number() {
    let tokens = tokenize("42");
    assert_eq!(tokens[0].kind, TokenKind::Number(42));
}
```

ここでの成果:

### Step 7. 参照・借用・可変参照

扱う内容:

ここでの成果:

---

### Step 8. `Result` / `Option` / `?` とカスタムエラー型

扱う内容:

- `Result<T, E>`
- `Option<T>`
- `?` によるエラー伝播
- `ParseError`, `EvalError` の定義
- エラー型への `Display` 実装
- エラー型への `std::error::Error` 実装

ここでの成果:

- 失敗を型で扱えるようになる
- 位置情報を使った、読みやすいエラーメッセージを出せる

技術的な整理:

- `Display` は、人間向けのエラーメッセージを出すために必要
- `Error` は、標準的なエラーハンドリングの流れに乗るために有用
- `?` はエラーを上位に返す記法であり、`Error` 実装そのものを直接必須にはしない

これは、traitを自分の型に実装する1回目の体験になる。

---

### Step 9. 評価器を作る + `Value` enum + `Display`

扱う内容:

- ASTの再帰評価
- `enum Value`
- `Value` への `Display` 実装

ここでの成果:

- `1 + 2 * 3` を実際に評価できる
- 異なる型の値を統一的に表示できる

これは、traitを自分の型に実装する2回目の体験になる。

補足:

- 1回目をエラー型、2回目を値の型にすることで、「traitはRustの設計パターン」として定着しやすくなる

### Step 13. モジュール分割

- 責務ごとにファイルを分け、1ファイルの限界を超えられる

---

### Step 14. テスト体系化

扱う内容:

- これまで書いたテストの整理
- 正常系・境界値・異常系の整理

重要:

## フェーズ2の実装ステップ

### テーマ

フェーズ2のテーマは、**成績計算・条件判定ツール**とする。

理由:

1. 入出力の意味が具体的で分かりやすい
2. 条件分岐や比較が、言語の用途と自然に噛み合う
3. 自分の現実とつながり、継続しやすい

### Step 1. CLI引数を受け取る

扱う内容:

- `std::env::args`
- 余裕があれば `clap`

ここでの成果:

- コマンドとして起動し、対象ファイルを指定できる

### Step 2. ファイルを読み込む

扱う内容:

- ルールファイルの読み込み
- 入力データファイルの読み込み

ここでの成果:

- 外部データを扱う下地ができる

### Step 3. 実データに対して言語を使う

扱う内容:

- 入力値を変数として環境に注入する
- ルールを評価して結果を返す

ここでの成果:

- 自作言語が現実の処理を動かし始める

### Step 4. エラー設計を改善する

扱う内容:

- ユーザー向けの分かりやすいエラー
- 位置情報の活用
- 複数エラーの収集と表示

ここでの成果:

- 他人が使っても壊れ方を理解しやすい

### Step 5. テストとリファクタリング

扱う内容:

- 統合テスト
- 関心ごとの分離の見直し
- 重複コードの整理

ここでの成果:

- 実務に近い保守性を持った状態にできる
- フェーズ2が完了する

## このプロジェクトで身につくRustの範囲

### しっかり身につく

- 基本型と制御構文（`i64`, `bool`, `if`, `while`）
- `String` と `&str`
- `Vec<T>`
- `HashMap<K, V>`
- `struct` と `impl`
- `enum` と `match`
- 所有権と借用の基本
- `Result<T, E>` / `Option<T>` / `?`
- カスタムエラー型
- `trait`（`Display`, `Error` を自分の型に実装）
- モジュール分割
- テスト
- CLIとファイルI/O

### 触れるが深くはない

- `Box<T>`
- ライフタイム注釈
- derive マクロ（`Debug`, `PartialEq` など）

### このプロジェクトでは薄い

- ジェネリクスの本格活用
- イテレータチェーンの高度な使い方
- クロージャ
- 非同期処理（`async` / `await`）
- 並行処理
- Webフレームワーク

補足:

- これらは「最初の本命プロジェクトで全部やる」対象ではない
- この計画のゴールは、後で出会ったときに既存の理解へ接続できる状態に入ること

## 完了条件

次を満たしたら、このプロジェクトは一旦完了とみなす。

1. 自作言語で算術、変数、条件分岐、ループ、`print` が動く
2. REPLまたはファイル実行ができる
3. 入力ファイルを読み、成績計算や条件判定ができるCLIがある
4. 位置情報付きのエラーメッセージが出る
5. テストをStep 3から継続的に書き、Step 14で体系化している
6. コードがモジュール分割されている
7. traitを最低2回（エラー型 + 値の型）自分の手で実装している
8. 各機能について「なぜ必要か」を自分の言葉で説明できる

推奨ロードマップ:

```text
ミニ言語プロジェクト
  ↓

```
