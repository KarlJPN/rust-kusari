# Step 3: TokenKind と Token を定義する（途中）

## 自己評価: 3/5

## 学んだ概念

### 1. enum — 種類を全部決めておく（どれか1つ）
- 「取りうる種類を事前に全部決めておく」仕組み
- 落とし物箱のラベルに例えると：文房具・衣類・電子機器・その他、のように種類を限定する
- 種類によっては追加情報を持てる（`Number(i64)` は中に整数を持つ、`Plus` はラベルだけ）
- C のクラス（オブジェクト指向）とは別物。enum は「モノ」ではなく「分類ラベル」
- enum の名前（`TokenKind` など）は自分で付けた名前で、そのまま型として使える

### 2. match — enum のどの種類かで処理を分ける
- `match` は `if` と違い、3つ以上の分岐を自然に扱える構文（関数ではない）
- 全パターンを書かないとコンパイルエラーになる（書き忘れを防ぐ）
- パターンの中で値を取り出せる: `Number(n)` の `n` は受け皿（変数名は自由）
- `n` には中の値が束縛される（`let n = 42` と同じことが自動的に起きる）
- 判断するのは `TokenKind::Number` の部分で、`(n)` は取り出し用の変数

### 3. struct — 複数の情報を1つにまとめる箱
- 関連する値をセットにして、1つの名前で持ち歩ける
- 住所カードや図書カードのように、複数の情報を1枚にまとめるイメージ
- ドット `.` で中身を取り出す（`pos.line`）
- struct の中に別の struct や enum を型として入れられる
- `Token` = `TokenKind`（種類） + `Position`（位置）をまとめたもの

### 4. usize 型
- 0以上の正の整数型
- 行番号や列番号のようにマイナスがない場面で使う

## なぜこれらが必要だったか
- 文字列を「意味のあるかたまり（トークン）」に分けるために、トークンの種類（enum）と構造（struct）が必要だった
- エラーメッセージで位置を伝えるために、Position をトークンに載せる必要があった
- match は enum の種類ごとに処理を分けるための道具

## まだ不安なこと
- struct の中に別の struct/enum を型として入れるところが最初ピンとこなかった
- 全体の構造が複雑になると混乱しやすい（一つずつなら理解できる）
- テストの書き方はまだ未学習
